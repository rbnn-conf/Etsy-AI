# ADR-010 — Functional XLSX as a first-class product format

Status: Accepted (2026-08-31)

## Context

Product #001 ships as print-ready PDFs generated by
`products/001-minimalist-monthly-budget-planner/render/` (hand-authored
HTML/CSS → Playwright/Chromium → PDF, network hard-blocked; 226-check QC;
Telegram review sends PNG previews only). That pipeline is unchanged.

A large share of the Etsy digital-product market for budgeting / planning
niches is **functional spreadsheets**: the buyer wants a workbook that
adds itself up, not a picture of one. We need XLSX to be a first-class —
and, for spreadsheet products, the primary — export, without disturbing
the PDF pipeline, the Etsy integration, or the Telegram approval flow.

## Decision

1. **A reusable engine, not per-product code.** New package
   `@dpf/spreadsheet` (`spreadsheet/`), its own npm package like
   `services/` and `products/*/render/`:
   - `src/engine/` — a thin, documented wrapper over **ExcelJS** (values,
     formulas, themed styles, merges, row/col sizing, number/currency/%
     formats, data validation + dropdowns, conditional formatting, data
     bars, freeze panes, print area / scaling, headers/footers, named
     ranges, sheet protection with formula cells locked and input cells
     left editable).
   - `src/design-system/` — **"Etsy Spreadsheet Design System v1"**:
     restrained tokens (typography, colour, spacing, borders, number
     formats, print) plus components (title block, section heading, data
     table with header/body/input/total rows, KPI card, callout, progress
     bar, checkbox column, status column). A product Design Spec overrides
     any token via `resolveTheme`.
   - `src/preview/` — headless PNG of the **actual** workbook:
     LibreOffice `--convert-to pdf` (recalculates on load) → `pdftoppm`.
     Helper/`veryHidden` sheets are stripped from a throwaway preview copy
     first (LibreOffice's headless PDF filter ignores sheet visibility).
   - `src/qc/` — reusable structural / formula-presence / formula-syntax /
     formatting / print checks, plus `recalcWorkbook()` (LibreOffice
     recalculation → CSV) for real known-input/known-output scenario
     tests. Formula *correctness* is never asserted from formula strings.
   - `src/spec/` — `SpreadsheetDesignSpec` contract + `validateSpreadsheetSpec`.

2. **Runtime: Node + ExcelJS, not Python + openpyxl.** The repo is
   Node/TypeScript throughout; adding a Python runtime + packaging
   convention for one engine is a bigger cost than one npm dependency in a
   new package (`services/` keeps its zero-runtime-dependency rule; the
   engine dependency is isolated in `spreadsheet/`). ExcelJS covers
   everything the products need. Its one gap — **it cannot write embedded
   charts** — is covered by conditional-formatting data bars and REPT()
   in-cell bars, which recalculate, print and survive customer edits.

3. **Preview renderer: LibreOffice headless.** Most faithful to how Excel
   lays the file out, and it recalculates formulas. Adds two documented
   system prerequisites (`libreoffice`, `poppler`); no new Node/runtime
   dependency for rendering, consistent with the PDF pipeline's use of a
   real headless renderer.

4. **ProductSpec gains two optional, backward-compatible fields**
   (`services/src/design/product-spec.ts`):
   - `primaryExport: { type: "pdf" | "xlsx" | "hybrid" }` — absent ⇒ `pdf`.
     When `xlsx`/`hybrid`, `exportFormats` must include `"xlsx"`.
   - `spreadsheet` — opaque here (like `designSystem`); the full contract
     lives with `@dpf/spreadsheet`. Products keep it in
     `products/<id>/xlsx-design-spec.json` and reference it.
   No DB migration yet — the persistence path (`ProductRepository`) is
   still deferred (ADR-008); a migration `0006` adds these columns when
   specs are actually persisted.

5. **Telegram review flow: additive only.** `ProductReviewSummary` gains
   optional `format` / `currency`; the headline shows a `Format:` line
   when present. `assembleSubmission` gains `preferVariant` so an
   XLSX product's `page-xlsx-NN.png` previews are shown instead of the PDF
   `page-a4-NN.png` set (both live in the same `storage/.../preview/`
   dir). Still PNG-only, still GBP, still no PDF/XLSX file sent, fake and
   real modes unchanged.

6. **Per-product build stays product-specific.**
   `products/001-*/xlsx/` (`build.mjs` / `preview.mjs` / `qc.mjs` /
   `cli.mjs`) mirrors the `render/` convention and depends on
   `@dpf/spreadsheet` via a `file:` dependency. Product #001 becomes a
   **hybrid** product: the 8 print pages are preserved as 8 functional
   worksheets; the PDFs are still built by `render/`.

7. **Canva is NOT a required dependency for product generation.** Neither
   the PDF pipeline nor the XLSX pipeline uses Canva. The
   `CanvaDesignProvider` boundary stays blocked/optional as in ADR-007.
   `ProductSpec` still rejects Canva-specific keys anywhere in the tree.

## Alternatives considered

- **Python + openpyxl** — most capable XLSX library, but introduces a
  second language runtime and packaging story for one component. Rejected
  for consistency; revisit only if ExcelJS proves limiting.
- **Render preview by converting XLSX → HTML and screenshotting with the
  existing Chromium** — no new system dependency, but a converter-built
  HTML is a re-creation, not the real file; formula recalculation and
  print layout fidelity are worse. Rejected: the preview must be the
  actual workbook.
- **Desktop-app screenshots (QuickLook / Excel automation)** — explicitly
  out; brittle, non-headless, not reproducible in CI.
- **Embed real charts via a different library** — no mature Node library
  writes charts into XLSX. Data bars + REPT() bars are more robust for a
  template anyway.
- **Put XLSX generation in `services/`** — breaks that tier's
  zero-runtime-dependency rule. Isolated in its own package instead.

## Consequences

- New package `spreadsheet/` (`@dpf/spreadsheet`), one runtime dependency
  (`exceljs`), fully tested (`npm test` in that package, including a
  LibreOffice-backed preview + recalculation test that skips cleanly when
  the tools are absent).
- New system prerequisites for preview/QC: `libreoffice` and `poppler`
  (`brew install --cask libreoffice`, `brew install poppler`, or
  `SOFFICE_BIN` / `PDFTOPPM_BIN`). The workbook *build* needs neither.
- `products/001-*/xlsx/` produces
  `storage/products/001/final/minimalist-monthly-budget-planner.xlsx`
  (the primary artifact for the spreadsheet edition) plus
  `storage/products/001/preview/page-xlsx-NN.png`. The PDF artifacts and
  their previews are untouched.
- Two QC reports now exist for #001: `qc-report.json` (print, 226 checks)
  and `xlsx-qc-report.json` (workbook). Wiring the XLSX QC result into the
  Telegram headline's QC line is a follow-up.
- Docs: `docs/XLSX_PIPELINE.md` (full workflow), `ARCHITECTURE.md`,
  `ROADMAP.md`, `services/README.md`, `products/README.md`,
  `storage/README.md`, `CLAUDE.md` updated.
